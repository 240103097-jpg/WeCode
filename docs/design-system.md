# Design planning

Status: **design not selected**. Do not treat this document as an approved visual system. A planning issue must present a coherent design reference or design-tool result, identify its source and usage rights, obtain owner selection and update this document before dependent UI implementation.

The selected design must document colors, typography, spacing, component states, responsive layouts and accessible focus/error/feedback behavior. Include sign up/sign in, track and level selection, lessons/practice and saved progress views. Screen grouping remains a proposal until selected.

Confirmed product constraints: English UI and educational content; Python, SQL and Git; editable level per track; Quiz, Fix the Bug and Complete the Code; clear feedback; retry/hint actions and a **separate Show Solution button**. Correct, incorrect and assisted outcomes must remain understandable without color alone. Do not invent points, completion badges or percentages before rules are approved.

Proposed accessibility baseline for owner review: keyboard operability, visible focus, semantic labels, readable code, sufficient contrast and usable narrow-screen layouts. Record concrete tokens and component examples after design selection; avoid introducing a UI framework before stack selection.
