# Task template

Use this structure for each GitHub implementation issue; PM refines it before work begins. Planning issues use the same structure with decision evidence as the deliverable.

## Goal

Describe the observable result and why it matters.

## Acceptance criteria

- [ ] One verifiable behavior per criterion, including relevant failure and boundary cases.
- [ ] Specify meaningful automated tests and manual evidence appropriate to this task.

## Out of scope

Name excluded work. Link a follow-up issue for required work moved elsewhere.

## Constraints

- Dependencies: link blocking issues; do not start until they pass QA.
- Record stage, confirmed decisions and relevant specification sections.
- Follow English-only product text, authored checking rules and the selected stack once approved.
- Engineer leaves issue open. Independent QA records every criterion and alone closes after PASS.

Handoff includes revision, changed behavior, actual test commands/results and known limitations. No invented test results or automatic closing keywords.
